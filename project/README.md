## 1. Паспорт проекта

- **Название проекта:** `RAG-система семантического поиска по Wikipedia на основе Natural Questions`
- **Автор:** `Батищев Илья Александрович`
- **Группа:** `БИСО-01-23`

- **Краткое описание (2-4 предложения):**  
  `Проект реализует систему семантического поиска (Retrieval-Augmented Generation) по базе знаний Wikipedia. Система принимает вопрос на естественном языке, находит релевантные фрагменты статей с помощью векторного поиска (FAISS) и возвращает контекст, содержащий ответ. В ходе работы сравнены классический вероятностный подход (BM25) и нейросетевой (Dense Retrieval), проведён tuning гиперпараметров, выбран оптимальный баланс качества и скорости. Результат упакован в FastAPI-сервис с Docker-контейнеризацией и покрыт тестами.`

Пример:

> Проект посвящён построению сервиса рекомендаций фильмов на основе пользовательских оценок.  
> Используются открытые датасеты, простые модели коллаборативной фильтрации и baseline-модели на контентных признаках.  
> Результат – REST API, который по идентификатору пользователя возвращает список рекомендованных фильмов.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта.
- `report.md` – подробный отчёт (постановка задачи, данные, эксперименты, результаты, архитектура).
- `self-checklist.md` – чеклист самопроверки перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - `02_retrieval_comparison.ipynb` – сравнение BM25 vs FAISS, расчёт метрик, визуализация.
- `src/` – основной модульный код:
  - `api/` – FastAPI сервис и Pydantic-схемы;
  - `data/` – загрузка, очистка HTML, чанкинг;
  - `retrieval/` – абстрактные интерфейсы и реализации BM25/FAISS;
  - `utils/` – метрики оценки и вспомогательные функции.
- `scripts/` – утилиты для сборки и оптимизации:
  - `build_indices.py` – предвычисление индексов;
  - `tune_bm25.py`, `tune_chunk_size.py` – grid search гиперпараметров.
- `data/` – подготовленные данные:
  - `processed/chunks.jsonl` – очищенные чанки Wikipedia;
  - `indices/` – сгенерированные индексы (игнорируются Git).
- `configs/` – конфигурационные файлы (`default.yaml`).
- `experiments/` – логи экспериментов (JSON-отчёты tuning).
- `artifacts/` – финальные артефакты (графики, таблицы метрик, сводка).
- `tests/` – модульные и smoke-тесты (`pytest`).

# 6. Построить индексы BM25 и FAISS

### 4.2. Запуск сервиса (API/веб-интерфейс)

# Убедиться, что виртуальное окружение активировано
# Запустить сервер
uvicorn src.api.main:app --reload --host 0.0.0.0 --port 8000


Сервис поднимается на http://localhost:8000. Доступна Swagger-документация: http://localhost:8000/docs

Ключевые эндпоинты:
GET /health – проверка статуса и загрузки индексов
POST /search – семантический поиск (параметры: query, method, top_k)
POST /answer – RAG-запрос (поиск + заглушка генерации ответа)
Пример запроса:

```bash
curl -X POST "http://localhost:8000/search" \
     -H "Content-Type: application/json" \
     -d '{"query": "who invented the telephone", "method": "faiss", "top_k": 3}'
```
4.3. Запуск через Docker
```bash
docker build -t nq-rag .
docker run -p 8000:8000 nq-rag
```

## 8. Ограничения и дальнейшая работа

Текущие ограничения:
> Корпус ограничен 5 000 чанков (прототип), не тестировалось на полном Wikipedia.
> Модель эмбеддингов оптимизирована под английский язык.
> Генерация ответов (/answer) реализована как заглушка (возврат наиболее релевантного чанка).
> Метрика F1@K низкая из-за методологии (сравнение короткого золотого ответа с большим текстом чанка).

Направления развития:
> Подключение локальной LLM (Ollama/Qwen) для полноценной генерации ответов.
> Добавление Cross-Encoder reranking для топ-20 результатов.
> Масштабирование на полный train сплит с использованием HNSW-индекса FAISS.
> Внедрение кэширования частых запросов и rate limiting.
